Turning Workers & Resources: Soviet Republic into a post-apocalyptic survival builder. Every mechanic you asked for is reachable — and four of the five are already half-built inside the vanilla game. This is what exists, what has to be written, and the order to do it in.

01 Verdict

The short version, before the detail.

Immigration Already in the game

Immigrants are a first-class vanilla concept — invitations, auto-invite toggles, separate source pools. You are re-pricing and re-pacing an existing system, not inventing one.

Scavenging economy Chain is complete

Demolition offices already yield waste_gravel and waste_steel; recycling plants already convert them back to gravel and steel. You need ruins to demolish, not a new industry.

Finite trade Needs a plugin

Customs house trade slots carry a content and a limit. Driving those from a stock model is the single highest-value piece of new C++ in the project.

New disasters Two viable routes

A scripted route needs zero reverse engineering and ships this week. A native route reuses the existing event roll for real severity and radius. Do both, in that order.

02 The five modding layers

Everything in this project lands on one of these. Cost rises steeply as you descend, so the discipline is to push each feature as high up the stack as it will go.

Data filesbuilding.ini · renderconfig.ini

04 Six things you don’t have to build

The scan turned up more existing scaffolding than expected. Each of these removes work from the plan.

Already shipped

The scrap loop is closed

waste_gravelrecycling takes 6.0 construction waste and returns 4.0 gravel. waste_steelrecycling takes 1.2 metal waste and returns 0.65 steel. Your bootstrap industry is a balance pass, not a build.

Already shipped

Immigrants are a real category

Separate from tourists and foreign workers, with their own counter in population statistics and their own invitation panel. The category you wanted to add is already the third one.

Already shipped

Price events are resource-generic

The market-shock message is assembled from a resource name plus a direction, not hard-coded to oil, iron and coal. Scarcity messaging for any commodity is a data problem.

Already shipped

Deposits can already be finite

A depletion plugin drains the deposit texture itself as mines extract. It survives saves, dims the minimap, degrades source quality, and keeps working if you later uninstall it.

Decoded this session

The text table is open

Big-endian header, an index of id / char-offset / char-length triples, then a UTF-16BE blob. A Python reader and writer now sits in tools/btf.py and round-trips the shipped file byte for byte.

Confirmed

Your loader hosts the good plugins

Republic Mod Loader accepts Tesmio API 3 and 4 plugins, which is the range TesmioLoader targets. Its resource, deposit, depletion, needs and building generators are reachable from the loader you already run.

05 The bootstrap chain

This is the survival opening the mechanics above produce — and every step of it exists in vanilla except the first.

ruined building→demolition office→waste_gravel→gravel recycling→gravel→construction
ruined building→demolition office→waste_steel→steel recycling→steel→construction
scrap field→salvage yard→ecomponents→electronics→advanced industry

Rows one and two need no new resources, no new recipes and no new building types — only ruins on the map and a demolition office in the starting kit. Row three is where the deposits plugin earns its place: electronic and mechanical scrap become new deposit types painted into the resource map, mined by a re-skinned mine, and drained by the depletion plugin so the scavenging era genuinely ends.

06 Hard limits

Four boundaries worth designing around now, rather than discovering in month three.

  • You cannot add a new building type. The $TYPE_* tokens are a compiled string-comparison chain, and each type has a matching arm in a 21 KB tick dispatcher. New behaviour has to be dressed as an existing type — a salvage yard is a mine, a shelter is a residential building.
  • Citizens hold at most seven simultaneous needs. The demand array is inline in the person record; enlarging it would move every field after it and break save compatibility. Budget your new survival needs against that ceiling.
  • Native work is pinned to one executable. Hooks are validated against the exact build. A game patch invalidates every RVA in the project at once, so keep the number of hooked addresses deliberately small and documented.
  • Scenario scripts read far more than they write. They see every building, person, vehicle and storage, but resource writes are not exposed — the Add* calls accumulate into a local total rather than depositing into a building. Anything that must move goods needs a plugin.

07 Build order

Sequenced so each phase is playable on its own, and nothing blocks on reverse engineering that has not happened yet.

1

Prove the pipeline

Ship one re-skinned ruin building, one custom text string and one trivial scenario script through the loader. Nothing here is interesting — the point is that the build, package and load path works end to end before any real content depends on it.

Deliverable — a workshop item that loads and shows your own name in your own words
2

The scavenging map

A landscape item with ruins placed across it and a starting kit built around a demolition office. Rows one and two of the bootstrap chain become playable using nothing but vanilla mechanics and your art.

Deliverable — the survival opening, fully playable, zero C++
3

Scripted disasters

A continuous scenario script that rolls its own events on any map and expresses them through fires, demolitions and citizen health. Radiation storms, structural collapse, raider attacks — all composable from primitives the VM already exposes.

Deliverable — new disaster types with no reverse engineering
4

Scarcity at the border

The first serious plugin. Rebuild customs house trade slots on first tick, drive their limits from a random stock model, and let them empty. This is the change that converts the game from city builder to survival, and it deserves to be built alone and tested hard.

Deliverable — finite, random, exhaustible imports
5

Immigration and scrap deposits

Free the invitation cost and pace arrivals off attractiveness. Register electronic and mechanical scrap as resources, declare them as deposit types, paint them into the resource map, and hand them to the depletion plugin.

Deliverable — population and salvage both become earned, not bought
6

Art pass

The long tail. Re-skin the building set to the theme, generate variants from donors where the shape allows, and replace the string table wholesale so the tone matches the mechanics.

Deliverable — the mod stops reading as a reskin of a Soviet game

08 Open questions

Three things I could not settle from the files alone, each of which changes a design decision:

Do the TesmioLoader plugins load cleanly under Republic Mod Loader? The declared API range says yes, and the compatibility host already classifies twelve of your current plugins as Tesmio-hosted — but those specific DLLs have not been observed running in your install. Worth a single test launch before phase five depends on it.

Can ruins be pre-placed as demolishable buildings in the map editor? Custom landscapes support modded buildings, so the mechanism exists. Whether a building placed at map-authoring time can be demolished for waste on day one of a save is an in-editor test, not a file question.

How much of the customs house window is safe to drive? The trade-slot rebuild point is documented, but whether limits can be written every tick without the panel fighting back is something only a running game will tell you.

Already in your repo. tools/btf.py reads and writes the game’s string table, and round-trips sovietEnglish.btf byte for byte across all 7,906 entries. tools/en.json holds the full English text as editable JSON — it is also the fastest way to search for a mechanic, since the game names everything it implements.
